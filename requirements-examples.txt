# Dependencies for tests/examples (the executed SKILL.md code blocks) and for
# `scripts/run_evals.py --run-executable`. Not needed to use the skills or for the
# stdlib-only default test suite.
#
#   pip install -r requirements-examples.txt
#   ML_AI_SKILLS_REQUIRE_EXAMPLE_DEPS=1 python -m unittest discover -s tests/examples -t tests -p "test_*.py"
#
# With ML_AI_SKILLS_REQUIRE_EXAMPLE_DEPS=1 a missing import FAILS instead of skipping
# (tests/examples/harness.py), so this file must list everything the tests import.
#
# Provenance: compiled from the `deps` each Phase 1 workstream reported for its example
# tests, and checked against `pip freeze` of the environment those tests passed in
# (CPython 3.13.2, Windows, 2026-10-27). Every pin below matched that environment except
# mlflow, bumped for security advisories (see its comment).
# Target interpreter: CPython 3.13 on Linux x86_64 (the CI `examples` job).
#
# This file pins the direct dependencies; anything they pull in that is not listed here is
# pinned by the lock constraints/examples-linux-cp313.txt, which CI installs with it:
#   pip install -r requirements-examples.txt -c constraints/examples-linux-cp313.txt
# The lock is for Linux x86_64 / CPython 3.13 only; on other platforms install without -c.
# Packages marked "(transitive)" are pinned here only because a workstream reported them as
# part of the environment its tests passed in. Bumping a pin here means regenerating the lock
# (docs/REPRODUCIBILITY.md "Dependency locks"); ci.yml's deps job fails until it is.
#
# CPU-only PyTorch: the +cpu builds live on the PyTorch index, not PyPI. Pinning the
# local version (+cpu) makes pip take torch/torchvision from that index and avoids the
# ~2 GB CUDA wheels. torchvision must match torch exactly: an unpinned
# `pip install torchvision` once tried to upgrade torch. The extra index is consulted
# for every package; all pins are exact, which limits what it can substitute.
--extra-index-url https://download.pytorch.org/whl/cpu
