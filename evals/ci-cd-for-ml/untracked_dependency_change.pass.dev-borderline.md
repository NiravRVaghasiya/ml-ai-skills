Read the CI logs first and find the exact failing step and assertion. "No code change" doesn't mean nothing changed: an unpinned dependency may have released a new version, the upstream data or schema may have shifted, or the runner image may have been updated. Compare the resolved package versions with the last green run (pip freeze, or your lock file) and diff the test data snapshot. Treat it as a real regression until you've found the cause. If the logs show a network timeout, re-run once, but never re-run until it passes, because a green rerun proves nothing about the cause.
