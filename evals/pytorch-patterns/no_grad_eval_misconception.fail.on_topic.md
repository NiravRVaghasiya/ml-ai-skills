Inside `torch.no_grad()` PyTorch knows you are not training, so no_grad puts the model in inference mode for you: gradients aren't computed and, since there's no backward pass, Dropout and BatchNorm have nothing to update. Dropout is effectively disabled under no_grad, so calling `model.eval()` as well is redundant. The jitter is more likely from shuffling or non-deterministic cuDNN kernels - set `torch.backends.cudnn.deterministic = True`.
