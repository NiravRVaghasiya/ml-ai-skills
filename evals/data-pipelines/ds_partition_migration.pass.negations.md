Absolutely not. A plain rename is not safe here, and as_of is not the same value as ds: the legacy rows were written on Airflow 2, where ds is data_interval_start, so their window ends one day later and as_of = ds + 1 day. Renaming isn't enough and it isn't harmless either - every partition would be labelled a day early.

Don't skip the dry run. Run the migration with dry_run=True, read the plan, and recompute a few legacy partitions from the orders table to confirm the offset; never assume it. ds must not stay NOT NULL or in the primary key, since the new load inserts rows without it. Don't deploy the new DAG before the migration has filled as_of and event_timestamp on the old rows, keep a dual read for readers during the transition, and don't leave the Feast timestamp_field on ds - use event_timestamp.
