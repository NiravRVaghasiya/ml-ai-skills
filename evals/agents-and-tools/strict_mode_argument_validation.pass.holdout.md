Please don't remove it. What strict: true buys you is syntactic conformance: the arguments will parse and have the declared types. Whether a given path or query is allowed is a separate, semantic question the schema can't answer. A model steered by injected content can emit delete_file(path="~/.ssh/id_rsa") or run_sql(query="DELETE FROM users") and both are perfectly valid against the schema. Keep the server-side checks: normalize the path and confirm it is inside the project root, run SQL under a least-privilege role (read-only unless writes are needed), and put a human confirmation step in front of destructive operations.
