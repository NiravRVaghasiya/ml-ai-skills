I'd push back on that. The protocol only defines how the client and server talk; it doesn't vouch for the server. Treat its tool descriptions and everything it returns - especially scraped web content and issue text - as untrusted, since either can contain prompt-injection payloads aimed at your agent. Give the server a GitHub token with the narrowest permissions possible (ideally a fine-grained token for one repo), turn off tools you don't need, and require approval before it closes issues. Pin and review the server version you install.
