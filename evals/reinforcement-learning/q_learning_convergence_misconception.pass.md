No - that's a common over-reading of "off-policy", and with your setup it's a real problem.

What off-policy buys you: Q-learning can learn about the greedy (target) policy from data generated by a different behavior policy. It does not mean any data is enough.

The tabular guarantee is conditional. Watkins & Dayan (1992) prove convergence to Q* when every state-action pair keeps being visited (infinitely often, in the limit) and the step sizes decay according to the Robbins-Monro conditions (sum of alpha diverges, sum of alpha^2 converges). Those are sufficient conditions, not necessary ones, but your data violates the first one outright: the controller never brakes, so Q(s, brake) gets no data at all.

With a neural network it's worse:
- The network still outputs a value for "brake" in every state, but that number is an extrapolation with nothing to correct it. Because the target takes a max over actions, an overestimated brake value gets bootstrapped into the other values, and errors can compound.
- With function approximation there is no convergence guarantee at all - function approximation + bootstrapping + off-policy data is the "deadly triad", which can diverge. Target networks and replay make DQN more stable in practice; they don't restore the guarantee.

What to do: collect data where braking actually happens (some exploration, e.g. in a simulator), or, if you're limited to these fixed logs, treat it as an offline-RL problem and use methods that keep the learned policy close to the logged actions (behavior-constrained or conservative Q-learning), then evaluate any policy that wants to brake very carefully before deploying it.
