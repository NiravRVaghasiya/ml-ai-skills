Using the full ticket table is fine here. Leakage is usually about the label itself leaking into a feature, and ticket counts aren't the label. More data is better for a count feature, since the extra tickets after the scoring date only make the signal less noisy, and the as-of cutoff matters mostly for the label window. The jump to 0.93 shows the feature is genuinely predictive, so you can ship it and monitor it in production.
